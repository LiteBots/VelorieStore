Dla twórców

API licencji

Każdy zakup w Velorie Store generuje klucz VEL-XXXX-XXXX-XXXX-XXXX. Twój plugin, skrypt lub mod sprawdza go przy starcie — jeśli klucz jest nieważny, unieważniony albo przekroczono limit serwerów, zasób się wyłącza.

Weryfikacja klucza

POST
PoleTypOpis
license_keystringKlucz klienta (wymagany)
product_idnumberID Twojego produktu — zalecane, blokuje użycie klucza z innego produktu. Znajdziesz je w panelu twórcy.
identifierstringStały identyfikator serwera (np. IP:port, adres cfx). Każdy nowy identyfikator zużywa 1 aktywację. Domyślnie: IP.
Odpowiedź — poprawna
{
  "valid": true,
  "license": {
    "product_id": 12,
    "product": "Advanced Garage System",
    "latest_version": "1.2.0",
    "owner": "GraczDemo",
    "activations": 1,
    "max_activations": 2
  }
}
Odpowiedź — błąd
{
  "valid": false,
  "reason": "activation_limit",
  "message": "Osiągnięto limit aktywacji (2)…"
}

// reason: missing_key | not_found |
//         wrong_product | revoked |
//         activation_limit

API zawsze zwraca status 200 z polem valid (429 przy nadmiarze zapytań — limit 120/min na IP). Klient może zwolnić aktywację: POST /api/v1/licenses/deactivate z tymi samymi polami.

Przykłady integracji


    


    

      
Nie ufaj klientowi
W FiveM weryfikuj tylko w server.lua. W Javie zaciemnij kod (np. ProGuard).

      
Tryb offline
Jeśli API jest nieosiągalne, możesz pozwolić na start z ostatnim poprawnym wynikiem z cache (np. 24h).

      
Aktualizacje
Porównaj latest_version z wersją pluginu i pokaż w konsoli informację o update.
